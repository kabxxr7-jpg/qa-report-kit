# BUG-NNN: short title that says what is wrong, not what you did

| Field | Value |
|---|---|
| ID | BUG-NNN |
| Status | New / Confirmed / Fixed / Verified / Rejected |
| Severity | S1 Critical / S2 Major / S3 Minor / S4 Trivial (how bad it is) |
| Priority (suggested) | P1 / P2 / P3 (when to fix it) |
| Area | e.g. Pricing, Cart, Validation, Layout, Keyboard |
| Build | name and version or commit of what was tested |
| Environment | browser and version, operating system, viewport, locale, any fixed clock or test data |
| Found by | name, date; test case id if one failed |
| Reproducibility | how many of how many attempts, and whether it depends on anything |

## Summary

One or two sentences: what is wrong and who it hurts.

## Preconditions

State the app must be in before step 1 (account, data, settings). Write "none" if there are none.

## Steps to reproduce

1. Numbered, one action each, exact values typed, exact buttons pressed.
2. Anyone who has never seen the app must be able to follow them.
3. Say where the problem appears.

## Expected result

What should happen, and why (the rule, the requirement or the reasoning).

## Actual result

What happens instead, with the exact text and numbers seen.

## Evidence

Screenshot, recording, log or request/response. Say what to look at in it. Redactions or highlights added to a screenshot are stated.

## Impact

Who is affected, how often, what it costs. Whether there is a workaround.

## Notes

Things that were tried and ruled out, related reports, a suspected cause if you are fairly sure (labelled as a guess), related test cases.

---

## How to fill this in (checklist)

- [ ] The title would still make sense in a list of 200 bugs.
- [ ] One problem per report. A second problem found on the way gets its own report.
- [ ] Steps were followed from scratch at least once, by you, after writing them.
- [ ] Expected and actual are both written down, with numbers where there are numbers.
- [ ] Severity describes the damage; priority describes the order of fixing. They are not the same.
- [ ] The environment is complete enough to reproduce on another machine.
- [ ] The evidence shows the problem without needing the text to explain it.
- [ ] No private data in the screenshot.
